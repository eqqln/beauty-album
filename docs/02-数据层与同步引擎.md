# 02 · 数据层改造与同步引擎

> 目标：让「手机 App」和「网站后台」读写同一份数据，任何一侧改动，另一侧刷新即可见。
> 涉及文件：`server/api/lib/db.php`、`server/api/lib/sync.php`、`server/api/index.php`

---

## 一、核心问题：主键对不上

| | App 端 | 后台 |
|---|---|---|
| 主键类型 | `UUID`（`A1B2C3D4-E5F6-...`） | `INT AUTO_INCREMENT`（`17`） |
| 子表引用 | `clientID: UUID` | `customer_id: INT` |

这是两边数据完全无法互通的根因。手机新建一个客户，id 是 UUID；后台新建一个客户，id 是 17。谁也不知道对方说的是谁。

### 解决：加 `uid` 映射列

每张业务表加一列 `uid VARCHAR(36)`，存 App 端的 UUID，建唯一索引：

```sql
ALTER TABLE customers ADD COLUMN uid VARCHAR(36) NULL COMMENT 'App 端 UUID';
ALTER TABLE customers ADD UNIQUE INDEX uk_uid (uid);
```

三条规则：

1. **App 推数据上来** → 按 `uid` 查后台行，有则 `UPDATE`，无则 `INSERT`
2. **后台新建数据** → 自动生成一个 UUID 写进 `uid`，App 拉下去就能认
3. **子表不存父表 INT id**，改存 `client_uid` / `agent_uid` 字符串

第 3 条是关键简化：照片知道「我属于客户 `A1B2C3D4-...`」，不需要知道后台给这个客户分配的是 `17` 号。这样两侧都能独立构造完整对象，同步时零翻译。

## 二、加 `updated_at` 做增量

```sql
ALTER TABLE customers ADD COLUMN updated_at DATETIME NULL;
```

`sync/pull` 带 `since` 参数时只返回 `updated_at >= since` 的行。

App 推送时如果带了 `updated_at`，服务端取它；没带则用服务器当前时间。这样手机离线改了三天再连上，时间戳仍是「三天前」，不会被误判成新数据。

## 三、补齐四张缺失表

IPA 有、后台原来连表都没有的：

```sql
CREATE TABLE appointments (          -- 预约排期
    id INT AUTO_INCREMENT PRIMARY KEY,
    uid VARCHAR(36) NULL,
    teacher_uid VARCHAR(36) NULL,    -- 导师 UUID
    teacher_name VARCHAR(60),
    client_uid VARCHAR(36) NULL,     -- 客户 UUID
    client_name VARCHAR(60),
    phone VARCHAR(30),
    service VARCHAR(120),            -- 项目名
    `at` DATETIME NULL,              -- 预约时间
    duration INT DEFAULT 60,         -- 时长（分钟）
    status VARCHAR(20) DEFAULT '待确认',
    note TEXT,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NULL,
    UNIQUE KEY uk_uid (uid),
    KEY idx_at (`at`),
    KEY idx_teacher (teacher_uid)
);

CREATE TABLE client_steps (          -- 护理步骤
    uid, client_uid, title, done TINYINT(1), done_at, note, sort
);

CREATE TABLE client_notes (          -- 客户笔记
    uid, client_uid, content
);

CREATE TABLE product_claims (        -- 产品领用
    uid, client_uid, product_uid, product_name, spec_name,
    qty, claimed TINYINT(1), claimed_at, note
);
```

表数从 21 张增加到 25 张。

## 四、补齐字段级差异

原表缺的字段，全部用 `add_column()` 增量补齐（MySQL 5.7 没有 `ADD COLUMN IF NOT EXISTS`，靠 `information_schema` 判存在）：

| 表 | 新增字段 | 对应 IPA |
|---|---|---|
| `customers` | `before_label` `after_label` | 自定义「使用前/后」文案 |
| `products` | `category` | `Product.category` |
| `products` | `usage_steps TEXT` | `Product.usageSteps: [String]` |
| `products` | `images TEXT`(JSON) | `Product.imageNames: [String]` |
| `agents` | `client_uids TEXT`(JSON) | `Agent.clientIDs: [UUID]` |
| `photos` | `tag` `file_name` `client_uid` | `PhotoItem.tag/fileName` |
| `payments` | `client_uid` | 关联客户 |
| `compares` | `client_uid` | 关联客户 |
| `agent_orders` | `agent_uid` | 关联代理 |

`agents.parent_id`（INT）保留不动，新增的 `parent_uid`（VARCHAR）走 App 同步 —— 老数据不受影响。

## 五、同步引擎 `lib/sync.php`

### 5.1 模块定义

12 个模块，每个声明「App 字段 → 数据库列」的映射：

```php
'customers' => [
    'table'  => 'customers',
    'map'    => [
        'name'         => 'name',
        'quoted_price' => 'quoted',     // 名字不同
        'created_at'   => 'created_at',
    ],
    'ints'   => ['progress'],
    'floats' => ['quoted'],
],
```

完整清单：

| 模块名 | 表 | 说明 |
|---|---|---|
| `customers` | `customers` | 客户 |
| `photos` | `photos` | 相册照片 |
| `compares` | `compares` | 对比图 |
| `payments` | `payments` | 收款 |
| `steps` | `client_steps` | 护理步骤 |
| `notes` | `client_notes` | 笔记 |
| `claims` | `product_claims` | 产品领用 |
| `teachers` | `mentors` | 导师 |
| `products` | `products` | 产品 |
| `agents` | `agents` | 代理 |
| `agent_orders` | `agent_orders` | 拿货 |
| `appointments` | `appointments` | 预约 |

### 5.2 类型转换

三个坑，都处理了：

**① 日期格式**

| 方向 | 转换 |
|---|---|
| App → DB | ISO8601 / 毫秒时间戳 → `YYYY-MM-DD HH:MM:SS` |
| DB → App | `DATETIME` → `date('c')`（`2026-11-12T14:00:00+08:00`） |

Swift 的 `ISO8601DateFormatter` 直接吃 `date('c')` 的输出，不需要额外处理。

**② 布尔 ↔ 枚举**

| App | DB |
|---|---|
| `available: Bool` | `status: '在岗' / '休息'` |
| `tags: [String]` | `tags: '皮肤管理,抗衰'` |
| `usageSteps: [String]` | `usage_steps: "第一步\n第二步"` |
| `clientIDs: [UUID]` | `client_uids: '["A1..","B2.."]'` |

**③ 数值类型**

映射表里 `ints`/`floats` 写的是 App 字段名（如 `quoted_price`），但数据库列名是 `quoted`。一开始只比对 App 字段名，导致 `quoted_price` 返回成字符串 `"1280.50"`。修法是两种名字都认：

```php
function sync_is(string $appKey, string $dbKey, array $list): bool
{
    return in_array($appKey, $list, true) || in_array($dbKey, $list, true);
}
```

实测修复后：`quoted_price = 1280.5`（float）、`progress = 0`（int）、`done = 1`（int）、`duration = 90`（int）。

### 5.3 四个核心函数

| 函数 | 作用 |
|---|---|
| `sync_pull($since)` | 全量或增量拉取 12 个模块 |
| `sync_push($payload)` | 按 `uid` upsert，返回每模块成功/跳过条数 |
| `sync_delete($payload)` | 按 `uid` 删除 |
| `sync_stats()` | 各模块行数（后台概览用） |

`sync_pull` 里有一条兜底：后台手工建的老数据 `uid` 是空的，拉取时自动补一个 UUID 并写回，保证 App 能识别。

`sync_push` 里每条记录单独 `try/catch`，一条脏数据不会让整批失败，只计入 `skipped`。

## 六、新增接口

| 路由 | 方法 | 鉴权 | 说明 |
|---|---|---|---|
| `sync/pull` | GET | admin token | `?since=2026-11-10T00:00:00+08:00` 增量，不传则全量 |
| `sync/push` | POST | admin token | body: `{"data": {"customers": [...], ...}}` |
| `sync/delete` | POST | admin token | body: `{"data": {"customers": ["uid1","uid2"]}}` |
| `sync/stats` | GET | admin token | 各模块条数 |
| `sync/login` | POST | 无 | App 用后台账号登录，拿 admin token |

`sync/login` 是给 App 用的：店主在手机上输入后台的邮箱/密码，拿到 token 后就能同步全店数据。支持邮箱、姓名、手机号三种登录方式。

## 七、通用 CRUD 的适配

后台原有的 `save` 接口做了三处改动：

1. **日期列统一转换** —— 新增 `dates` 声明，`datetime-local` 和 ISO8601 都转成 `DATETIME`
2. **自动补 `uid`** —— 后台新建任何一行，自动生成 UUID
3. **自动写 `updated_at`** —— 新增和更新都写，App 才能增量拉到

`list` 接口加了两处：

1. **`client_uid` / `agent_uid` / `teacher_uid` 可作为筛选条件**
2. **自动回填父级名字** —— 子表查出 `client_uid` 后，批量查 `customers` 补一个 `client_name`，列表里显示人名而不是 UUID

## 九、注意事项

- **唯一索引降级**：老库里如果有重复 `uid`，`UNIQUE INDEX` 会失败，`add_index()` 会自动降级成普通索引，不阻断部署。
- **`sync_push` 只写表里真实存在的列**，用 `column_exists()` 逐列校验，字段对不上时跳过而不是报错。
- **单条上限**：`sync_pull` 每模块最多 20000 行，超出需分批。
- **删除是硬删除**，没有回收站。App 端删客户会连带后台一起删，做删除同步前建议先在后台「数据备份」留一份。
