# 01 · 功能解析与前后台差异诊断

> 生成时间：2026-11-10
> 对象：`BeautyAlbum` IPA（1.1.0 / build 8） ↔ `meiyan.shengka.net` 后台
> 结论：**不搭配。后台 17 个模块里，IPA 只真正联动了 3 个（套餐 / 会员 / 充值钱包），其余 12 类业务数据全在手机本地，一条都不同步。**

## 三、差异清单

### 3.1 后台有、IPA 完全没有的（12 项）

`payments` `customers` `photos` `compares` `mentors` `products` `agents` `agent_orders` `subs(部分)` `sms` `backup` `settings(写)`

后台建一条客户，手机上看不到；手机拍一张照片，后台也没有。**两边各存一份，互不相干。**

### 3.2 IPA 有、后台完全没有的（5 项，后台连表都没有）

| IPA 功能 | 后台缺什么 |
|---|---|
| **预约排期** | 无表、无界面。导师哪天有空、客户约了几点，后台看不到 |
| **护理步骤** | 无表。每位客户的疗程做到第几步，后台看不到 |
| **客户笔记** | 无表。App 里记的文字，后台看不到 |
| **产品领用** | 无表。客户用了哪个产品、领没领，后台看不到 |
| **店铺设置 / 收款码 / 锁屏 / 功能开关** | `settings` 表有，但没有对应字段和界面，IPA 也不上传 |

### 3.3 字段级差异（即便同一概念，两边字段也对不上）

| 概念 | IPA 字段 | 后台字段 | 问题 |
|---|---|---|---|
| 客户报价 | `quotedPrice` | `quoted` | 名字不同 |
| 产品简介 | `intro` | `desc` | 名字不同 |
| 产品使用步骤 | `usageSteps: [String]` | `steps TEXT` | 数组 vs 文本 |
| 产品图片 | `imageNames: [String]` | `cover VARCHAR` | 多图 vs 单图 |
| 产品规格 | `specs: [ProductSpec]` | `specs TEXT` | 结构不同（后台没拆） |
| 导师在岗 | `available: Bool` | `status VARCHAR('在岗')` | 布尔 vs 枚举 |
| 代理上级 | `parentID: UUID?` | `parent_id INT` | UUID vs 自增 ID，**根本无法映射** |
| 代理名下客户 | `clientIDs: [UUID]` | 无 | 缺字段 |
| 照片标签 | `tag` | 无 | 缺字段 |
| 照片文件名 | `fileName` | 无 | 缺字段 |
| 收款方式 | `method` | `method` | 一致 |
| 预约 | 完整对象 | 无 | 缺整张表 |

**最致命的是主键类型：IPA 用 UUID，后台用自增 INT。** 这是两边数据无法互通、也无法做增量同步的根因 —— 手机新建的客户 id 是 `A1B2C3D4-...`，后台是 `17`，谁也对不上谁。

## 四、修复方案

### 4.1 主键映射：加 `uid`

给后台每张业务表加一列 `uid VARCHAR(36)`，存 App 端的 UUID，建唯一索引。

- App 推数据上来：按 `uid` 找到后台行，有则更新、无则插入
- 后台新建数据：自动生成一个 UUID 写进 `uid`，App 拉下去就能识别
- 子表（照片/步骤/笔记/收款/领用/拿货）用 `client_uid`、`agent_uid` 字符串直接引用父表，**不需要把 INT id 翻译成 UUID**

这一条解决「主键对不上」，是全部联动的基础。

### 4.2 补齐后台缺的四张表

```sql
appointments    预约      uid, teacher_uid, teacher_name, client_uid, client_name,
                          phone, service, at, duration, status, note
client_steps    护理步骤  uid, client_uid, title, done, done_at, note, sort
client_notes    客户笔记  uid, client_uid, content
product_claims  产品领用  uid, client_uid, product_uid, product_name, spec_name,
                          qty, claimed, claimed_at, note
```

### 4.3 增量同步协议

```
POST sync/pull   {since}        → 返回 since 之后变更的全部模块
POST sync/push   {模块: [记录]}  → 按 uid upsert
POST sync/delete {模块: [uid]}   → 按 uid 删除
POST sync/stats                 → 各模块条数
POST sync/login  {account,password} → App 用后台账号登录，拿 admin token
```

每张表加 `updated_at`，App 推送时带 `client_updated_at`，服务端取 `max` 后落库，避免旧数据覆盖新数据。

### 4.4 IPA 端

新增 `SyncService`：登录后台账号 → `sync/pull` 全量 → 与本地 JSON 合并 → 本地任何写操作后 `sync/push` 增量。图片走 `upload` 接口转 URL。

**不改主界面和现有功能**，只加一层同步，入口放在「账号」页。
