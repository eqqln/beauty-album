# 08 · 激活码与软件授权

> 版本：IPA 1.5.0 (build 13) · 后台已上线 `meiyan.shengka.net`
> 完成时间：2026-11-11

## 这一轮解决什么

上一版 1.4.1 的联动是全的（13 个模块自动双向），但**软件本身没有授权闸门**：IPA 装到任何一台 iPhone 上都能直接用，充值卡只是往会员钱包加钱，管不到"这台机器能不能用"。门店把安装包发出去就收不回来了。

这一轮把激活码做成**授权层**，并和充值打通：

- 装完第一次打开 → 必须输入激活码，没激活进不了主界面
- 一张码 = 种类 + 授权时长 + 可激活设备数 + 随卡充值（金额 / 赠送 / 积分）
- 激活完自动接管同步：服务端同时签发**设备同步凭证**，不用再手动登录一次店铺账号
- 后台可生成 / 导出 / 停用 / 恢复 / 删除 / 充能续期，能看到每台设备的剩余时间

## 数据模型（schema 5）

新增 4 张表，`db.php` 的 `SCHEMA_VERSION` 由 4 升到 5：

| 表 | 作用 | 关键列 |
|---|---|---|
| `activation_codes` | 激活码本体 | `code`（前缀+12位，去 0/O/1/I）、`kind`、`duration_value`/`duration_unit`/`duration_minutes`、`max_devices`、`used_count`、`amount`/`bonus`/`points`、`start_at`/`expire_at`、`status` |
| `activations` | 已激活设备 | `code_id`、`device_id`、`license_key`（本机凭证）、`expire_at`、`status`（生效中/已停用/已过期/已解绑）、`last_seen_at` |
| `activation_logs` | 生成/激活/充能/停用/删除流水 | `action`、`minutes`、`amount` |
| `device_tokens` | 设备同步凭证 | `token`、`activation_id`、`device_id`、`expire_at` |

时长统一按**分钟**存（`小时 60 / 天 1440 / 周 10080 / 月 43200 / 季 129600 / 年 525600`，0 = 永久），这样小时级试用码也能表达。原来 `license-save` 想改一个不存在的 `days` 列，已改成 `duration_value + duration_unit` 由服务端重算 `duration_minutes`。

## 接口

App 端（公开，不需要登录）：

| 路由 | 说明 |
|---|---|
| `license/config` | 返回 `required / notice / contact / grace_days`，App 用它决定要不要弹激活页 |
| `license/redeem` | 兑换：入参 `code / device_id / device_name / platform / app_version`，返回 `license_key` + `sync_token` + 到期信息 + 随卡充值结果 |
| `license/verify` | 启动/回前台复核，被停用或过期返回 403 |
| `license/claim` | 会员登录后补领随卡充值 |

后台（`perm_check_cap($a,'license')`）：

`admin/license-stats` / `license-settings` / `license-generate` / `license-list` / `license-devices` / `license-logs` / `license-save` / `license-void` / `license-device-void` / `license-boost` / `license-delete` / `license-export`

## 两个必须先修的坑

**1. 能力位不存在 → 后台一调就 403。**
`perm_check_cap($a,'license')` 在 12 个路由里用着，但 `perm.php` 的 5 个角色预设里**都没有 `license` 这个 key**，`perm_check_cap` 取不到就是空 → 连店主都被拒。已给 5 个角色补上（店主 true，其余 false），后台员工管理里的能力勾选项也加了「激活码授权」。

这和上一轮 `ipa` 能力位漏定义是同一类错误：新能力位必须同时出现在 `perm_roles()` 和后台 `CAP_LABEL` 里。

**2. 设备凭证拿不到同步权限。**
`sync_authorize()` 写在 `license.php` 里但没人调用，`sync/pull|push|delete|stats` 和 `upload` 仍然只认管理员 token —— 那样"激活完自动同步"就是句空话，装完还得手动登录一次。已改成：

- `sync/*` → `sync_authorize()`：管理员 token（要有 `sync` 能力）或有效设备凭证，二选一
- `upload` → `upload_authorize()`：管理员（要有 `write`）或有效设备凭证

设备凭证进不了后台管理接口，只能同步和传图。

## App 端

新增两个文件，`RootView` 改了三行：

- `Services/LicenseService.swift`：设备编号（首次启动生成 UUID 存本地）、启动复核、兑换、本地到期判断（含宽限期）、把 `sync_token` 交给 `SyncService.adopt()`
- `Views/ActivationView.swift`：激活页（粘贴、联系门店弹窗、设备编号、复核按钮）+ 启动校验中的过渡页
- `RootView`：`checking → 过渡页 / inactive → 激活页 / 已激活 → 锁屏或主界面`，授权通过后才 `SyncService.activate()`

离线策略：**网络问题不锁人**，只有服务端明确返回停用/过期/解绑才踢回激活页；本地到期时间 + 宽限期过了也直接拦。

## 使用流程

1. 后台「激活码」→ 生成（选种类、时长、设备数、随卡充值）→ 复制明文码
2. 把码发给门店/客户，对方装 1.5.0 包后打开，第一屏就是激活页
3. 输入码 → 激活成功 → 自动开始同步（不需要再登录店铺账号）
4. 续费：后台「充能」给单台设备或整张码 +N 天，App 下次复核即生效
5. 停用：后台「停用」整张码或单台设备，App 立刻无法使用，数据仍在服务器

## 边界

- `license_key` 存 UserDefaults（与店铺 token 一致），没进 Keychain；越狱设备可以拷贝，但服务端有设备数限制和停用开关兜底
- 激活码明文只在生成弹窗显示一次，之后列表只显示 `MYA-XXXX-XXXX-XXXX` 格式化后的码，导出 CSV 才有全量
- 换机重装用同一张码重新激活即可；旧设备记录会标成「已解绑」，不占名额
- 证书签名仍然依赖用户的开发者证书，出的是无签名包，安装报「无法安装」多半是证书过期
