### 2.3 较新者胜

用旧时间戳推同一条客户：

```json
{"saved":{"customers":{"saved":0,"skipped":1}}}
```

换新时间戳：

```json
{"saved":{"customers":{"saved":1,"skipped":0}}}
```

→ 后台改得更晚时，手机的旧数据不会覆盖回去。

## 四、踩过的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `quoted_price` 返回字符串 `"1280.50"` | `ints`/`floats` 里写的是 App 字段名，数据库列名不同 | 加 `sync_is()`，两种名字都认 |
| 照片推送 `skipped: 1` | `photos.url` 是 `NOT NULL`，App 新拍还没上传时没 URL | 模块加 `defaults => ['url' => '']` |
| 「所属客户」显示 `#11111111-...` | `ref` 缺 `showKey`，回填的 `client_name` 用不上 | schema 补 `showKey: 'client_name'` |
| `Call to undefined function backup_size_text()` | 运维脚本 require 顺序不全 | 补 `backup.php` |
| `manifest.plist` 版本没变 | `ipa_current()` 只读不写 | 显式调 `ipa_write_manifest('1.2.0')` |
| 后台图标显示成方块 | `🪜`(Emoji 13) / `🖼`(需 VS16) 兼容性差 | 换 `✅ 📔 🏷️ 📷 🔀` |
| 同步面板读出 `"正在读取…"` 卡住 | `loadSyncPanel()` 没在 `view.innerHTML` 之后调用 | 补调用 |

## 五、当前边界

- **同步是手动的**，没有后台定时或前台自动触发
- **删除是硬删除**，App 删客户会连带后台删除，建议先「数据备份」
- **冲突粒度是整行**，不是字段级
- **首次全量同步照片多的店会慢**（每张 200–500KB）
- **客户详情没有聚合页**，照片/步骤/笔记/收款/领用分散在 5 个菜单
- **预约只有列表**，没有日历视图
