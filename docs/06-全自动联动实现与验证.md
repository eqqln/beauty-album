# 全自动联动 · 实现与验证

> 版本：IPA **1.3.0 (build 10)** · 后台 `meiyan.shengka.net`
> 完成时间：2026-11-10
> 本轮目标：把"手动点同步"改成"什么都不用点，自己就同步"

---

## 一、这一轮到底改了什么

上一版（1.2.0）已经有双向同步接口，但**要用户自己点"立即同步"按钮**。这一版把触发全部自动化：

| 场景 | 1.2.0 | 1.3.0 |
|---|---|---|
| 手机里加顾客 | 点按钮才上传 | **1 秒后自动上传** |
| 手机里改预约 | 点按钮才上传 | **1 秒后自动上传** |
| 后台加了顾客 | 点按钮才下载 | **60 秒内自动下载** |
| 后台改了店铺设置 | 点按钮才下载 | **60 秒内自动下载** |
| 从别的 App 切回来 | 不会自动拉 | **切回前台立刻拉一次** |
| 登录后 | 要手动点一次 | **登录完成即自动跑一轮完整同步** |

一句话：**装好、登录一次，之后两边永远自己对齐，不需要再点任何按钮。**

## 二、两条自动通道

### 2.1 手机 → 后台（本地一改就推）

`SyncService.observeLocalChanges()` 用 Combine 监听 `Store` 的 6 个 `@Published`：

```
$clients / $teachers / $appointments / $products / $agents / $settings
        │
        ├─ debounce(1.0s)   ← 连续操作只算一次，避免边打字边推送
        │
        ├─ markDirty(模块名)  ← 标记哪些模块需要推
        │
        └─ schedulePush()
              └─ 再等 1.2s → runSync(doPull: false)
```

**为什么是 1 秒 + 1.2 秒**：
- `debounce(1.0)` 吸收输入抖动，用户连打 5 个字只触发 1 次；
- 额外 1.2 秒是给"刚拍完照还没写完文件"、"刚改完名字紧接着改电话"留合并窗口；
- 两者相加约 2.2 秒，体感上"改完就同步好了"，又不会把服务器打满。

**防自激**：拉取合并时会写 `Store`，如果不拦，合并完又会触发推送，形成死循环。所以合并前设 `suppressPushUntil = now + 3s`，这 3 秒内的变化不登记为脏。

### 2.2 后台 → 手机（定时拉 + 回前台拉）

`SyncService.startPeriodicPull()`：

```
每 60 秒  → runSync(doPull: true, silent: true)   ← 静默，不弹进度
切回前台  → pullIfActive()                        ← scenePhase == .active
App 启动  → activate() 里先跑一轮
```

`silent: true` 的含义：不显示进度条、失败不弹错误。后台同步应该是"无感"的，用户不该被"同步中…"打扰。只有用户主动点"立即同步"时才显示进度和错误。

**增量拉取**：请求带 `since` 参数（上次同步的服务端时间），服务端只返回 `updated_at > since` 的行。第一轮是全量，之后都是增量，数据量再大也不会卡。

## 三、13 个模块的字段对照

服务端 `sync_modules()` 定义 App 字段名 → 数据库列名的映射。**App 用 UUID，数据库用自增 INT，靠 `uid` 字段桥接，不做 id 翻译。**

| App 模块 | 数据库表 | 关键字段映射 | 类型处理 |
|---|---|---|---|
| customers | `customers` | `quoted_price → quoted` | float / int(progress) |
| photos | `photos` | `phase → 使用前/使用后` | `url` 有默认空串 |
| steps | `client_steps` | `done` 0/1 | int |
| notes | `client_notes` | — | — |
| claims | `product_claims` | `product_uid` 字符串引用 | int(quantity/claimed) |
| payments | `payments` | `client_uid` | float(amount) |
| appointments | `appointments` | **`date → at`** | int(duration) |
| compares | `compares` | — | — |
| teachers | `mentors` | `available ↔ 在岗` | bool ↔ 中文字符串 |
| products | `products` | `usage_steps` 数组 ↔ 换行文本 | JSON(specs/images) |
| agents | `agents` | `client_uids` JSON | JSON |
| agent_orders | `agent_orders` | `agent_uid` | float/int |
| settings | `settings` 键值表 | 单条记录，`uid = shop` | JSON(step_template/features) |

### 踩过的坑（都已在代码里修掉）

1. **`quoted_price` 返回字符串 `"1280.50"`**
   `ints`/`floats` 里写的是 App 字段名，但数据库列名是 `quoted`，匹配不上。
   → 新增 `sync_is($appKey, $dbKey, $list)`，两种名字都认。

2. **照片推送永远 `skipped: 1`**
   `photos.url` 是 `NOT NULL`，App 新拍的照片还没上传，`url` 是空。
   → 模块加 `'defaults' => ['url' => '']`。

3. **预约时间在后台显示空白**
   App 叫 `date`，数据库列叫 `at`（`date` 是 MySQL 保留字）。
   → `map` 里显式写 `'date' => 'at'`，`list` 接口按 `at` 返回，后台表单字段也叫 `at`。

4. **后台"所属客户"显示 `#11111111-...`**
   下拉框只拿到了 uid，没拿到人名。
   → `schema.js` 的 `ref` 加 `valueKey: 'uid'` + `showKey: 'client_name'`，`crud.js` 列表优先用 `showKey`；`list` 接口自动回填 `client_name`。

## 四、图片也跟着自动走

文字数据之外，三类图片有独立通道（`uploadImage` / `fetchImage`）：

| 类型 | 云端路径 | 触发 |
|---|---|---|
| 客户照片 | `client/<uid>/<文件名>` | 推送前先扫一遍本地缺的 |
| 导师头像 | `teacher/<uid>` | 同上 |
| 产品图片 | `product/<uid>/<文件名>` | 同上 |
| **微信/支付宝收款码** | `shop/wechat_qr` · `shop/alipay_qr` | 同上（本轮新增） |

逻辑是"先补图再推数据"：`runSync` 的顺序固定为
**删 → 传图 → 推数据 → 拉数据 → 合并 → 下图**。
这样后台看到的照片地址一定不是空的。

单张上限 11 MB，超了跳过不报错。

## 五、冲突处理：谁后改谁算数

两边同时改同一条，用 **LWW（Last-Write-Wins）**：

```php
// sync_push() 里
if ($serverTs > $clientTs + 1) { $skip++; continue; }   // 服务端更新，拒绝旧数据覆盖
```

- 时间戳精确到秒，留 1 秒容差（防止设备时钟微差导致误判）；
- 被拒绝的行计入 `skipped`，不报错；
- 服务端时间永远以 `+08:00` 存，App 传 ISO8601 进来统一转 `DATETIME`。

## 六、本轮实测记录

### 6.1 后台加顾客 → 手机能拿到

```
POST ?r=save  m=customers  name=王雅静  phone=13912345678
              note=微信号 wangyj88，敏感肌  quoted=3980  progress=20

返回: {"ok":true,"id":2,"uid":"82EA619E-1D80-4307-80C2-ABBE2EB00CF2"}

GET  ?r=sync/pull
customers[1] = {"uid":"82EA619E-...","name":"王雅静","phone":"13912345678",
                "note":"微信号 wangyj88，敏感肌","quoted_price":3980,
                "progress":20,"created_at":"2026-11-10T17:24:26+08:00"}
```

`quoted_price` 是 **float 3980**（不是字符串），`progress` 是 **int 20**，日期是 **ISO8601** —— 类型全部正确，App 能直接解码。

### 6.2 后台加导师 → 手机能拿到

```
teachers[0] = {"uid":"2F544357-...","name":"李老师","title":"高级皮肤管理师",
               "phone":"13700001111","available":true,"tags":[]}
```

`status="在岗"` 正确转成 `available: true`。

### 6.3 手机推预约 → 后台自动出现

```
POST ?r=sync/push
{"appointments":[{...teacher_uid:李老师, client_uid:王雅静, service:光子嫩肤,
                  date:"2026-11-15T10:30:00+08:00", duration:60, status:已确认}],
 "steps":[{...title:"第 1 次光子嫩肤", done:0}],
 "notes":[{...content:"手机端记的：下次降低能量"}]}

返回: {"saved":{"appointments":{"saved":1,"skipped":0},
                "steps":{"saved":1,"skipped":0},
                "notes":{"saved":1,"skipped":0}}}

GET ?r=list&m=appointments
{"uid":"A1B2C3D4-...","client_name":"王雅静","teacher_name":"李老师",
 "service":"光子嫩肤","at":"2026-11-15 10:30:00","duration":60,"status":"已确认"}
```

**`client_name` 自动回填成"王雅静"**，后台列表直接显示人名，不是一串 UUID。

### 6.4 店铺设置整段同步

```
settings[0] = {"uid":"shop","shop_name":"美颜相册","before_label":"使用前",
               "after_label":"使用后","wechat_qr":"","alipay_qr":"",
               "pay_link":"","pay_note":"","step_template":[],"features":[],
               "home_layout":"竖排列表","home_columns":2,"home_limit":0,
               "show_cover":1,"updated_at":"2026-11-10T17:15:35+08:00"}
```
